Setting up REAP

This page assumes you have not typed a command into a computer since about 2005, and that you are not especially keen to start now. That is roughly the right amount of caution for a tool that is going to hold your bank details. Everything is written out in full: what to type, what should happen, and what to do when it doesn't.

Two things before you start.

REAP is pre-release, and the source repository is private. You need to have been given access to it. If you can open github.com/talktalkmake/reapbooks and see a list of files rather than a "404", you have it. If you get the 404, stop here — nothing below will work yet, and that is not your fault.

Steps 1–9 take about twenty minutes and get you as far as issuing a real invoice. Step 10 — keeping your ledger in Google Sheets — is optional, is the fiddliest part of the whole thing, and can wait for a different afternoon.

Nothing on this page can break your computer.

  • Every command below either installs a well-known program or creates a folder. Nothing is deleted.
  • If you get lost, close the window and walk away. Nothing is left half-finished that matters.
  • REAP never asks you for a password. Not once, anywhere. If a password box appears, it is your Mac or it is Google asking — not REAP.
  • Undoing all of it is three lines, at the bottom of this page.

First: the terminal

The terminal is a window where you type an instruction and press Return, and the computer does it. It looks unfriendly and it is not. It is a text box.

  • On a Mac: hold ⌘ and press Space, type Terminal, press Return.
  • On Windows: click Start, type PowerShell, press Enter.

You will get a window with a line of text ending in % or $ and a blinking cursor. That is the prompt. It means: waiting for you.

How to use this page: click into the terminal window, paste a command (⌘V, or right-click on Windows), press Return, and wait. Some commands take a minute and print nothing at all while they work. When the prompt comes back, that command is finished.

A few commands below use $HOME instead of ~ when a folder is being handed to a program rather than typed after cd. That is not a typo: cd ~ works everywhere, but Windows PowerShell won't expand a bare ~ inside a command's arguments the way it does after cd, and $HOME is the one spelling that works unchanged on a Mac, Linux and Windows PowerShell alike. Paste these exactly as shown.

One thing that startles everybody: when you type something secret — an account number, a Social Security number — nothing appears on screen. No dots, no stars, nothing. It is not broken and it is not ignoring you. It is deliberately not putting your account number where the person behind you can read it. Type it and press Return.

Step 1 · Install Node

REAP is written in JavaScript. Node is the free program that runs JavaScript on your own machine. You may already have it. Ask: 

node --version

If it answers with a number of v20.11 or higher, you are done here:

v22.14.0

If instead it says command not found, go to nodejs.org, download the version marked LTS, open the file it downloads, and click through the installer accepting everything. Then quit the terminal entirely and open a new one — it only notices new programs when it starts — and ask again.

Step 2 · Install Claude Code

REAP has no buttons and no windows. You talk to it. Claude Code is the program that does the talking, and it also runs on your machine. 

npm install -g @anthropic-ai/claude-code

That prints several lines and takes a minute. Then check it, and sign in when it asks: 

claude

To leave Claude at any point, type /exit and press Return.

If this step fails with a wall of red text containing EACCES or permission denied, that is your machine declining to let a program install itself system-wide. Do not fight it with the terminal; follow the official installer at docs.claude.com/en/docs/claude-code/setup instead, which handles this properly.

Step 3 · Get REAP

cd ~
git clone https://github.com/talktalkmake/reapbooks.git

cd ~ means "go to my home folder" — the one with Documents and Downloads in it. git clone downloads a copy of REAP into a new folder called reapbooks.

On a Mac, a box may pop up offering to install "command line developer tools". Click Install, wait for it to finish, then run the git clone line again. That is macOS fetching git for you; it is a normal Apple installer.

You may be asked to sign in to GitHub. That is GitHub checking you are one of the people allowed to see a private repository.

If you get Repository not found, that is the private-repo gate, not a typo. You have not been given access yet.

Step 4 · Set it up, and make the word reap work

cd ~/reapbooks
npm install
npm link

npm install fetches the single outside piece of code REAP uses. (One. That is a deliberate decision, not an oversight — every dependency is a stranger with write access to your machine.) npm link teaches your terminal the word reap.

Check it:

reap --version
0.0.0

If npm link failed with a permissions error, do not worry about it. Everywhere below that says reap, type this instead: 

node $HOME/reapbooks/bin/reap.js

So reap init --workspace $HOME/my-books becomes node $HOME/reapbooks/bin/reap.js init --workspace $HOME/my-books. Longer, identical result.

Step 5 · Make your books folder

reap init --workspace $HOME/my-books

You get back something like this:

Workspace ready at /Users/you/my-books

  created  ./
  created  assets/
  created  expenses/2026-09/
  created  statements/2026-09/
  created  invoices/2026-09/
  created  .gitignore

That folder is now yours, and it is where everything lives:

  • expenses/2026-09/ — money out. Drop receipts and bills in here.
  • statements/2026-09/ — the CSV you download from your bank.
  • invoices/2026-09/ — money in. REAP writes the invoices it generates here.
  • assets/ — put your logo here, as logo.png.

The month folders are not decoration. Bookkeeping is a monthly ritual, and a single flat folder turns "which of these belong to September" into a question you will eventually answer wrong.

.gitignore is a small text file that tells version-control software to never upload the contents of this folder. It is written on day one, before there is anything in there to protect, because a tool that waits until it notices a problem has already lost that race.

Step 6 · Introduce REAP to Claude

claude mcp add reap -- reap serve --workspace $HOME/my-books

In plain English, that line says: there is a tool called reap; to start it, run this; and it may only ever look inside ~/my-books.

The last part matters more than it looks. The folder is fixed at the moment the tool starts, and no instruction given in a conversation can move it — including text that arrived from a receipt someone else wrote or an email a client sent.

Step 7 · Tell REAP about your business

cd ~/my-books
claude

Then type, in ordinary words:

Set up my business profile in REAP.

It will ask you about:

  • Your legal name — the name a cheque gets made out to — and your trading name if they differ.
  • Your address, email, phone, website.
  • Whether you are a sole proprietor, an LLC, an S-corp, and so on.
  • How you want to be paid, and your default terms (net 30, due on receipt).
  • What your invoice numbers should look like.

It will not ask for your tax ID or your bank account. That is the next step, and it is on purpose.

When it finishes there is a file called profile.json in ~/my-books. You can open it in a plain text editor and read it — TextEdit on a Mac, Notepad on Windows. It is yours, it is plain text, and it never leaves your machine.

Step 8 · The two things you type yourself

Leave Claude with /exit, and run these two in the terminal: 

reap set-tax-id --workspace $HOME/my-books
reap set-bank --workspace $HOME/my-books

Why these two are different.

Your tax ID and your bank details are never sent to a language model. But if the model had asked you for your routing number and you had typed it in reply, it would be sitting in the conversation just the same. So REAP refuses to accept them that way at all. These two commands read what you type and write it straight into the file on your disk, mode 0600 — readable by your account and nothing else.

Some things you will see, and should expect:

  • Nothing appears as you type the number. Correct, and deliberate. Type it and press Return.
  • A mistyped routing number is rejected immediately. Nine digits carry a check digit, and REAP does the real arithmetic on it. This is the one field where a typo silently sends a client's money to a stranger, so it is checked while you are still sitting there. It confirms the number is well formed; it does not prove the account exists, and REAP says so rather than implying otherwise.
  • If your tax ID is a Social Security number, it will never be printed on an invoice. You are not asked whether you would like that. The file is not able to express it.

Step 9 · Your first invoice

Back in claude, from inside ~/my-books:

Preview an invoice to Ridgeline Partners for 12 hours
of design work at $150 an hour.

Preview changes nothing. It does the arithmetic and shows you the document. No invoice number is used up — a number is allocated at the moment you issue, never at draft, so an abandoned draft leaves no gap in your sequence.

When it looks right:

Issue it.

You get a PDF and an HTML file in invoices/2026-09/. Open the PDF. Check the payee line and the total with your own eyes — this is the document that goes to a client, and it is worth looking at properly the first time.

The PDF depends on nothing: no web font, no stylesheet, no logo fetched from anywhere. It will open the same way in five years on a machine with no internet, and it does not call anyone when your client opens it.

If a client requires a purchase-order number and you have not given one, REAP refuses to issue the invoice at all. It is not being difficult. Their accounts-payable system would have rejected it silently, three weeks from now, while you assumed you were getting paid.

Step 10 · The Google Sheets ledger optional

You can stop reading here. Everything above works on its own, and REAP will keep issuing invoices quite happily without this step. Come back when you want it.

What you get: one spreadsheet, in your own Google Drive, holding your invoices, clients and expenses. It is where the hand-off to your accountant actually happens, and it is a normal spreadsheet you can correct by hand. It is also what makes the duplicate-invoice-number check real: REAP asks the sheet which numbers already exist before issuing a new one.

Why it is fiddly: REAP has not registered its own application with Google yet. Until it does, you make one — in your own Google account. It is about five minutes of clicking in an interface designed for developers, and it is the least pleasant part of this page. None of it costs anything.

a. Make a Google Cloud project

Go to console.cloud.google.com, and use the project dropdown at the top to create a new project. Call it anything — My books is fine.

b. Turn on the Sheets API

In the left menu: APIs & Services → Library. Search for Google Sheets API, open it, press Enable.

c. Fill in the consent screen

APIs & Services → OAuth consent screen. Choose External, put your own name and email in the required boxes, and save. When it offers a Test users list, add your own Google address.

d. Create the credentials

Credentials → Create credentials → OAuth client ID, and for application type choose Desktop app. Google shows you a Client ID and a Client secret. Copy both.

Despite the name, that "secret" is not a password to your account, and it is not sensitive the way your bank details are: in a desktop application it necessarily ships inside the program, which is precisely why the sign-in flow is built not to rely on it.

e. Sign in

In the terminal, pasting your own two values in place of the dots:

export REAP_GOOGLE_CLIENT_ID=...
export REAP_GOOGLE_CLIENT_SECRET=...
reap connect --workspace $HOME/my-books

Those two export lines last only as long as this terminal window. If you close it and run reap connect again another day, set them again first. On Windows PowerShell the two lines are $env:REAP_GOOGLE_CLIENT_ID="..." and $env:REAP_GOOGLE_CLIENT_SECRET="...".

f. The scary screen

Your browser will open Google's sign-in, and then show you: "Google hasn't verified this app."

That is expected, and here is exactly what it means. The unverified app is the one you created ten minutes ago, in your own account. Google reviews applications that ask for access to other people's data; nobody has reviewed yours because it has exactly one user, which is you. Click Advanced, then the "go to … (unsafe)" link.

Then read what it asks for. It should be one permission, and only one: see, edit, create and delete only the specific Google Drive files you use with this app. That is the narrow one. REAP can touch the spreadsheet it makes and nothing else in your Drive — not your documents, not your photos, not any other spreadsheet. If the screen asks for anything broader than that, something is wrong; close it and say so.

g. Done

REAP creates the spreadsheet and prints its address:

Created "Your Business — books" in your Google Drive:
  https://docs.google.com/spreadsheets/d/...

The sign-in token is stored outside your books folder, in your own account's private application-data location, readable only by you: ~/Library/Application Support/reap/credentials.json on a Mac, %APPDATA%\reap\credentials.json on Windows. Note that it is not in your books folder. That is on purpose: the books folder is the one you might someday put under version control, and a standing key to your spreadsheets has no business being in something that can be uploaded.

When something goes wrong

What you seeWhat it means
command not found: node Node isn't installed, or you didn't quit and reopen the terminal after installing it. Step 1.
command not found: reap npm link didn't take. Use the long node $HOME/reapbooks/bin/reap.js form from step 4.
Repository not found The repository is private and your GitHub account hasn't been given access. Nothing you can fix at your end.
Something about no profile.json You're ahead of yourself — run the interview in step 7 before set-tax-id, set-bank or connect.
The routing number was rejected A digit is wrong. Nothing was saved. Run reap set-bank again and retype it.
No Google OAuth client is configured The two export lines in step 10e, in the same terminal window as reap connect.
A wall of red with EACCES A permissions refusal from your own machine. It is not REAP failing, and it is not dangerous — see the note in step 2.

When REAP itself refuses to do something, it tries to tell you what it actually found rather than printing a code. If a receipt's figures do not add up, for instance, you get the sum: 

amount: does not match subtotal plus tax: 16.50 + 1.32 = 17.82,
but the total says 18.40 (out by 0.58). Check the receipt — a missed
tip line or a misread digit looks exactly like this.

What REAP will never ask you for

  • A password. There is no REAP account, so there is nothing to have a password to.
  • A signup, an email address, a licence key, an activation. None of these exist.
  • Permission to send anything anywhere. There is no telemetry, no analytics, no crash reporting, no "anonymous usage data".

Your tax ID and your bank details stay in one file on your disk. They are never sent to a model, and they are never included in anything REAP sends anywhere else. That is not a promise about how carefully the code was written — it is enforced by tests that run on every single change, and the tests are in the repository next to the code.

Undoing all of it

claude mcp remove reap
rm -rf ~/reapbooks
rm -f ~/Library/Application\ Support/reap/credentials.json

On Windows PowerShell, the last two lines are: Remove-Item -Recurse -Force $HOME\reapbooks and Remove-Item -Force $env:APPDATA\reap\credentials.json. (PowerShell's rm is an alias for Remove-Item and doesn't understand the combined -rf flag the Mac/Linux line above uses.)

That removes the tool, REAP's own code, and the Google sign-in. Your books folder ~/my-books is left exactly where it is — the invoices, receipts and statements in it are your records, and no uninstaller should be deleting those. Drag it to the bin yourself if you want it gone.
